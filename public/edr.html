The EDR Analogy

There is no ps for agent work.

Endpoint security already lived through this exact problem and solved it — by changing what it kept records about. Agent tooling hasn't had that moment yet. This is the argument, borrowed rather than invented.

01 · The problem antivirus couldn't see

Every step is fine. The sequence is the attack.

Antivirus asked one question per file: is this hash on a known-bad list? Stateless, per-event, no memory of anything before it. That worked while malware was a file you downloaded.

Four unremarkable events. Every checker says yes.

A per-event checker cannot see a sequence, because it has no subject that persists long enough to have one. That is the entire limitation, and it's the same one agent gateways have today.

02 · What EDR actually changed

It didn't block better. It changed the subject.

Endpoint Detection and Response — CrowdStrike, SentinelOne, Defender — records what happens on a machine continuously: process launches, parent-child relationships, file reads, network connections. The breakthrough wasn't detection quality. It was giving the system a durable object with lineage to reason about.

Two things became possible that were structurally impossible before: behavioral detection — a sentence like "this document spawned a shell that contacted a new domain" can only be written if you kept the lineage — and retroactive investigation, the daily motion of every incident responder: find something bad, then ask what touched it and what it spawned.

03 · The transplant

Agent tooling is at the antivirus stage.

Gateways check calls one at a time against policy. That's the file scanner. What doesn't exist anywhere is the tree — no record of which job a call belonged to, what that job read, or what it produced. Every tool call is an orphan.

The last row is the one that lands with a security person. Finding a bad hash and querying which machines ran it and what those processes spawned is the most common investigative move in the field — done weekly, by everyone. For agent work that query isn't slow or expensive. It's impossible, because the subject it asks about doesn't exist.

05 · The objection, and the answer

"Won't the gateway just add this?"

Firewalls did not kill CrowdStrike. Network security did not absorb endpoint security. Both categories are enormous and both still exist, because they sit in different places and therefore see different things. A network tap cannot observe what a process did with a file already on disk — not because the vendor hasn't gotten to it, but because of where it sits.

To be precise about it: the gateway is not blind to incoming data. It's a proxy, so it sees both directions of anything that crosses it — a Confluence page fetched through it is fully visible. The limitation isn't in versus out. It's transits versus bypasses.

Coverage of what entered the model is only as good as coverage of the channels it entered through — and the gateway is one channel among many. Neither vantage point alone sees the whole picture. That's an argument for a second one, not a feature request to the first.

06 · Sequencing

Visibility first. Control second.

Nobody bought EDR to stop things. They bought it to finally see what was happening on their machines, and blocking arrived later, once the telemetry had earned trust. The order matters, because it decides what this gets pitched as.

1987 — 2010
Antivirus. Per-file verdicts. Works until attacks span time and legitimate tools.
2013
EDR named as a category. The subject becomes the process. Sold on visibility, not blocking.
2015 — 2020
Adoption follows breaches. Telemetry becomes non-optional; response features arrive after trust.
Now
Agent gateways. Per-call verdicts. No durable subject. Same limitation, new domain.

We attack a funded incumbent at their strongest point, with a story that only makes sense to companies that already run approval bureaucracy.

If we lead with

A gap anyone can verify in a single customer conversation. Control becomes the consequence, and it arrives second — if at all.

07 · Say this before they do
The honest part

EDR was a hard sell for years.

Heavyweight, invasive, endless complaints about performance and about installing one more thing on every machine. The category only became non-optional after enough breaches made the telemetry impossible to argue with.

That is exactly the timing risk here, and anyone in endpoint security already knows it. Name it first — volunteering the weakness reads as judgment, getting caught by it reads as a pitch.

The thing that would make this inevitable — the first agent-caused incident a company publicly cannot explain — hasn't happened yet. Whether that means start now or wait is a real question, not a rhetorical one.

08 · How to present this

Assert the diagnosis. Hedge the solution.

These are two different claims and they don't deserve the same confidence. Wrapping both in the same tentative framing makes the defensible half sound as unsupported as the open half, and the room discounts everything.

Say with conviction
  • There is no durable unit of agentic work
  • Every tool call is an orphan event
  • A proxy can't record what never crosses it
  • Nobody can answer "what did that source affect"
  • This is the shape EDR already solved once
Defensible today, against a skeptic.
Say as genuinely open
  • Who feels this most, and how badly
  • What the right atom of the record is
  • Whether result sets are actionable or noise
  • Where instrumentation should sit
  • Whether it's forensics or reporting
Unknown until the conversations happen.

The order to put them in

01 · assert
The gap. No ps for agent work.
02 · assert
Why the incumbent can't close it. Vantage point, not roadmap.
03 · assert
What I'm deliberately not doing. Enforcement comes second — that's the order EDR won in.
04 · open
What I don't know. Specific, not vague. Specificity here reads as rigor.
05 · open
How I'll find out. Ten conversations, a fixed set of questions, a decision rule set in advance.

Unknowns placed last read as rigor. The same unknowns placed first read as a disclaimer, and everything after them is heard through it.

The line that does the most work

"If fewer than three of ten have a real story about not being able to answer what an agent touched, the timing answer is not yet."

Naming a falsifiable decision rule — before running the test — is the strongest available signal that this is an investigation and not a pitch. It costs nothing and it's the thing a skeptical room is actually listening for.

If the room is customers
Lead with the gap. Stay quiet about the vision.

You want their story, not their agreement. The moment you describe the solution they start being helpful, and the data is worthless.

If the room is investors or collaborators
The open questions are the asset.

Section 04 is what they're evaluating. Make it specific and show the test is already designed.

Same material, opposite emphasis. The failure mode is running the customer version for investors, or the investor version for customers.

09 · The sixty-second version
Say it like this

You know how antivirus checked one file at a time, and it fell apart against attacks that spread across processes and time? EDR fixed that by changing the subject — instead of scoring files, it recorded processes, with parents, children, and history. Once that object existed you could do behavioral detection, and you could ask the question that actually matters after the fact: this file was bad — which machines ran it, and what did those processes spawn?

Agent tooling is at the antivirus stage. Gateways check calls one at a time. There's no process tree — no record of what job a call belonged to, what that job read, or what it produced. So when a document in your knowledge base turns out to be wrong or poisoned, nobody can tell you what it affected. The honest answer is "we don't know," and it stays that way.

The gateway can't fix it, for the same reason your firewall vendor didn't kill CrowdStrike. It's a proxy — it sees everything that crosses it, in both directions, and nothing that doesn't. Pasted text, local files, built-in web fetch, prior turns, retrieval that happens inside the app: none of that touches the wire, and all of it ends up in the window. Different vantage point. That's the gap.
